# DARK Games v5.4.1 — главная для телефона

Обновление поверх подготовленной версии 5.4.0. Главная получила более свободную композицию: первый экран с кнопками, баннер, отдельный блок мира с переходами в лор и правила, затем новости. Первоначально видны три новости, кнопка добавляет ещё шесть из загруженных записей (API по-прежнему возвращает до 30).

Добавлены появления блоков при прокрутке и переходы содержимого страниц. Учитываются отключение анимации в аккаунте и prefers-reduced-motion телефона. При отсутствии IntersectionObserver блоки остаются видимыми; без View Transitions работает прежнее CSS-появление страницы.

Для обновления интерфейса с 5.4.0 достаточно заменить вместе public/index.html, public/styles.css и public/app.js. Полный проект тоже приложен. База, Volume и переменные Railway не требуют изменений. Работа выполнялась с локальной копией 5.4.0: изменения, сделанные позже непосредственно в GitHub, нужно сравнить перед заменой файлов.

Проверки синтаксиса и существующие HTTP/DOM-тесты прошли. Реальная визуальная проверка на телефоне не выполнена. Изменения не опубликованы в GitHub/Railway.

# DARK Games v5.4.0

Обновление на основе v5.3.1 Railway Hotfix. Сохранены Express, SQLite, структура данных и тёмное оформление.

## Новое

- Страница `/play` с инструкцией, кнопкой копирования IP и актуальной версией из настроек.
- Кнопки на главном экране, правила в верхней навигации, упрощённые тексты связи и кланов.
- Поиск по заголовкам и тексту лора, ссылки `/lore#chapter-ID`, копирование ссылки.
- Независимая загрузка публичных разделов с повтором при ошибке и таймаутом запросов.
- Состояния «Проверяем» и «Нет данных». Статус по-прежнему задаёт администрация, это явно подписано.
- Смена пароля отзывает прежние сессии, текущая получает новую cookie. Есть выход на всех устройствах.
- Новые изображения проходят декодирование, ограничение 16 мегапикселей и преобразование в WebP до 2560×2560. Анимированные/многостраничные изображения не принимаются. Для аватаров ограничена частота загрузки.
- Образцы цветов перенесены из встроенных HTML-стилей в CSS, сохранена строгая CSP.
- Отдельная страница 404, JSON 404 для неизвестных API, заголовки вкладки при переходах.
- Lockfile, `npm ci` в Docker, автоматические проверки и команда резервного копирования.

## Обновление с v5.3.1

1. Останови старое приложение и сохрани полный каталог данных (включая базу и uploads) и `.env`. На Railway сохрани данные Volume средствами доступного тебе резервного копирования. Не удаляй Volume.
2. Замени код содержимым новой версии, сохрани свои `.env` и данные. Не переноси `node_modules` между версиями или операционными системами.
3. Установи зависимости: `npm ci`. Нужен Node.js 24.
4. Для проверки выполни `npm run check` и `npm test` (тесты используют отдельную временную базу и порт 3199).
5. Запусти `npm start`. На Railway оставь прежние переменные и подключённый Volume.
6. После обновления всем пользователям потребуется войти снова: старые токены без версии сессии больше не принимаются. Аккаунты, пароли и контент сохраняются. Колонка `session_version` добавляется автоматически.

Для отката останови приложение и восстанови старый код вместе с резервной копией данных.

## Скриншот мира и условия входа

Для реального скриншота уже есть место под первым экраном: создай активный баннер в админке, загрузи изображение сервера и поставь его первым в списке. Публично показывается первый активный баннер. Изображение из реального мира не приложено к исходному архиву, поэтому вымышленное фото не добавлялось.

В `public/index.html`, раздел `data-page="play"`, уточни редакцию Minecraft, моды, порядок доступа и правила Hardcore после решения администрации. Сейчас текст честно предлагает уточнить эти условия. IP и версия берутся из настроек.

## Резервная копия

Команда запускается при остановленном приложении, чтобы база и изображения относились к одному состоянию:

```bash
npm run backup -- /absolute/path/outside-data
```

Без аргумента копия создаётся в `backups/`. Команда сохраняет SQLite через `VACUUM INTO`, копирует uploads и создаёт `COMPLETE.txt` после успешного завершения. Храни копию отдельно от диска/Volume сайта. `.env` сохрани отдельно и приватно.

Восстановление: останови приложение, сохрани текущий каталог данных отдельно, восстанови `dark-games.db` и `uploads/` из завершённой копии в чистый каталог данных и запусти сайт. Не смешивай восстановленную базу с прежними файлами `-wal`/`-shm`. При пользовательских `DB_PATH` и `UPLOADS_DIR` используй их реальные пути.

## Что проверено

- Синтаксис серверного и клиентского JavaScript.
- HTTP-сценарии регистрации, прав администратора, смены пароля и отзыва сессий, публикации новостей/лора, валидной и поддельной картинки, страниц 404.
- Клиентские DOM-тесты отказа одного API и повтора, поиска, прямых ссылок на главы и маршрутов.
- Локальная команда резервного копирования.

Визуальная проверка в браузере не завершена: браузер среды блокирует локальный адрес. Реальный Discord OAuth и развёртывание Railway не проверялись. Автоматический мониторинг Minecraft и управление кланами в эту версию не входят.

# DARK Games v5.3 — Railway Ready

Это версия v5.2 с доработкой хранения данных для Railway. Дизайн, аккаунты, CMS, персонализация и роли сохранены.

## Что изменилось

- SQLite и все загружаемые изображения теперь могут жить внутри **одного постоянного каталога** `DATA_DIR`.
- По умолчанию локально используется `./data`.
- Изображения теперь сохраняются в `data/uploads/`, а наружу по-прежнему доступны как `/uploads/...`.
- Старые картинки из `public/uploads/` при запуске автоматически копируются в новое хранилище, если их там ещё нет.
- Добавлен `/api/health` для проверки состояния приложения.
- Railway автоматически распознаётся как reverse proxy.
- В production secure-cookie включается автоматически.
- Node.js закреплён на ветке 24.x.

## Локальный запуск

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Открывай:

```text
http://localhost:3000
```

Твои локальные данные будут храниться в:

```text
data/dark-games.db
data/uploads/
```

## Если обновляешься с v5.2

Сохрани свои:

```text
.env
data/dark-games.db
public/uploads/
```

Можно распаковать v5.3 в новую папку, затем перенести туда `.env` и `data/dark-games.db`. Старые изображения из `public/uploads/` тоже перенеси, если они есть. При первом запуске они автоматически скопируются в `data/uploads/`.

Не удаляй старый проект, пока не убедишься, что новая версия работает.

# Railway — короткая настройка

## 1. GitHub

Загрузи проект в GitHub. `.env`, база и пользовательские изображения специально исключены через `.gitignore`.

## 2. Railway

Создай проект из GitHub-репозитория. Railway должен автоматически выполнить установку зависимостей и `npm start`.

## 3. Variables

В Railway добавь переменные:

```env
NODE_ENV=production
JWT_SECRET=сюда_длинный_секрет_не_короче_32_символов
ADMIN_USERNAME=darkadmin
ADMIN_PASSWORD=твой_пароль
DATA_DIR=/app/data
SITE_SERVER_IP=darkgamespro.falix.pro
MINECRAFT_VERSION=1.21.1
```

`PORT` вручную на Railway задавать не нужно.

Для Discord потом добавь:

```env
DISCORD_CLIENT_ID=...
DISCORD_CLIENT_SECRET=...
DISCORD_REDIRECT_URI=https://ТВОЙ-ДОМЕН/auth/discord/callback
```

## 4. Persistent Volume

Добавь к сервису **Volume** и укажи Mount Path:

```text
/app/data
```

Именно в нём будут находиться одновременно:

```text
/app/data/dark-games.db
/app/data/uploads/
```

Поэтому новые деплои сайта не должны стирать пользователей, новости, лор, настройки, аватары и баннеры.

## 5. Публичная ссылка

После успешного deploy открой настройки Networking и создай Railway domain. Полученную HTTPS-ссылку можно открывать с телефона и отправлять другим людям.

## Проверка

После публикации открой:

```text
https://ТВОЙ-ДОМЕН/api/health
```

Нормальный ответ:

```json
{"ok":true}
```

## Важно про ADMIN_PASSWORD

Как и раньше, `ADMIN_PASSWORD` создаёт пароль первого администратора. Если администратор уже существует в постоянной базе, простое изменение этой переменной не меняет его существующий пароль.
