# Размещение «Мандаринового Комплекса»

Подготовлено 24 сентября 2026 года для владельца **liryzliryz34@gmail.com**.

Один сервер будет обслуживать справочник, Google-вход и панель `/admin`. Список сотрудников, заявки и журнал будут храниться на постоянном диске. Исходники готовы; новый сервер и OAuth-приложение ещё не созданы. Наличие почты в настройках не даёт доступ к твоему аккаунту Google.

## Стоимость и что потребуется

Вариант ниже использует Render и закрытый репозиторий GitHub. Нужны аккаунты этих сервисов и доступ к своему проекту Google Cloud. Пароль Google вводится только на странице Google.

Ориентир по тарифам Render: **$7 в месяц за сервер + $0,25 за диск на 1 ГБ = $7,25 в месяц**. Это базовая стоимость без налогов и возможного превышения включённых лимитов. Итоговую сумму проверь в Render перед созданием. Файл `render.yaml` описывает платный сервис; сам архив ничего не оплачивает. Отдельный платный домен для первого запуска не нужен.

Бесплатный сервер Render не поддерживает необходимый постоянный диск. Без него список доступов потеряется при замене экземпляра сервера. Для текущей реализации выбран один процесс с SQLite на диске.

## 1. Загрузить исходники в закрытый репозиторий

1. Распакуй архив исходников на компьютере.
2. На [GitHub](https://github.com/new) создай репозиторий, например `mandarin-events`, с видимостью **Private**.
3. Через **Add file → Upload files** загрузи содержимое распакованной папки, сохраняя вложенные папки. Загружается не ZIP, а файлы из него.
4. В корне репозитория должны лежать `render.yaml`, `package.json`, `package-lock.json` и папки `server/`, `dist/`. Сохрани загрузку кнопкой **Commit changes**.

Не добавляй реальный `.env`, ключи Google, базу SQLite или `node_modules`. В подготовленном архиве их нет. Доступ к репозиторию означает доступ ко всем материалам справочника: не делай его открытым.

## 2. Создать сервер из готовых настроек

Открой [Render Dashboard](https://dashboard.render.com/) → **New → Blueprint**, подключи GitHub и выбери этот закрытый репозиторий. В качестве файла конфигурации оставь `render.yaml`.

Перед созданием проверь предложенную конфигурацию:

| Настройка | Значение из файла |
| --- | --- |
| Тип | Web Service, Node.js |
| Регион | Frankfurt |
| Тариф | `0.5c-512mb` — 512 МБ, прежнее название Starter |
| Количество экземпляров | 1 |
| Build Command | `npm ci --omit=dev --ignore-scripts` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Постоянный диск | 1 ГБ, путь `/var/data` |
| Автоматические деплои по коммитам | Выключены |

Применение Blueprint создаёт платные ресурсы. Когда решишь запускать, подтверди создание в Render и дождись первого успешного развёртывания. Скопируй выданный HTTPS-адрес вида `https://имя-сервиса.onrender.com` из страницы сервиса. Точное имя назначает Render — не используй пример вместо своего адреса.

Пока ключей Google нет, открывается страница с неактивным входом, а материалы остаются закрытыми. Успешная проверка `/healthz` означает работу процесса и базы, но не готовность Google-входа.

Адрес автоматически берётся из `RENDER_EXTERNAL_URL`. `PORT` задаёт Render. **Не копируй локальный `.env` на сервер**: его адрес `127.0.0.1` предназначен для компьютера разработчика.

## 3. Подключить Google

Открой [Google Cloud Console](https://console.cloud.google.com/) под `liryzliryz34@gmail.com` и создай проект «Мандариновый Комплекс».

В **Google Auth Platform** заполни:

| Раздел | Что указать |
| --- | --- |
| Branding | Название приложения «Мандариновый Комплекс», свою почту для контактов |
| Audience | External для команды с личными Gmail; при тестовом запуске добавь свою почту и проверяющего сотрудника в Test users |
| Data Access | Только базовые `openid`, `email`, `profile`; доступ к Drive и Gmail не нужен |
| Clients → Create client | Тип **Web application**, имя, например «Сайт ивент-отдела» |
| Authorized redirect URIs | Твой точный HTTPS-адрес плюс `/auth/google/callback` |

Пример формата адреса возврата:

```text
https://имя-сервиса.onrender.com/auth/google/callback
```

Поле **Authorized JavaScript origins** для этой серверной схемы не требуется. Если Google запрашивает адрес приложения, укажи `https://имя-сервиса.onrender.com/login.html`, а сведения о данных находятся на `/privacy.html`. Требования к домену и публикации выполняй по подсказкам консоли Google.

Создай клиент и сохрани **Client ID** и **Client Secret**. Секрет вводится на хостинге; не загружай его в репозиторий и не присылай в чат.

## 4. Включить вход на сервере

В Render открой созданный сервис → **Environment → Edit**. Добавь две переменные:

| Имя | Значение |
| --- | --- |
| `GOOGLE_CLIENT_ID` | Client ID созданного Web-клиента |
| `GOOGLE_CLIENT_SECRET` | Его Client Secret |

Остальные настройки уже заданы Blueprint:

| Имя | Значение |
| --- | --- |
| `OWNER_GOOGLE_EMAIL` | `liryzliryz34@gmail.com` |
| `AUTH_DB_PATH` | `/var/data/google-auth.sqlite` |
| `HOST` | `0.0.0.0` |
| `NODE_VERSION` | `24.19.0` |

Сохрани переменные и запусти развёртывание через действие сохранения с деплоем или **Manual Deploy → Deploy latest commit**. Дождись успешного запуска.

Затем открой сайт и войди Google-аккаунтом **liryzliryz34@gmail.com**. В шапке появится **«Доступ команды»** — это панель `/admin`. Только назначенный аккаунт получает права владельца.

До выдачи адреса всей команде проверь:

- Владелец входит и видит панель.
- Добавленная в панели почта сотрудника получает справочник после Google-входа.
- Посторонний аккаунт видит ожидание допуска, а не документы.
- После отзыва допуска новые запросы сотрудника отклоняются.
- В приватном окне без входа адрес `/data.js` не показывает материалы.

Для постоянного использования проверь статус приложения в Google Auth Platform → Audience и выполни требуемую Google публикацию. Публикация OAuth-приложения не отменяет список допусков на сайте. Если консоль запрашивает подтверждение бренда или домена, его должен завершить владелец проекта.

## 5. Где управлять дальше

| Где | Что делать |
| --- | --- |
| Сайт → «Доступ команды» (`/admin`) | Добавлять почты, одобрять заявки, отзывать доступ, смотреть журнал за 30 дней |
| Сайт → `/admin/help` | Читать встроенную памятку |
| Render → сервис | Смотреть состояние, перезапускать, менять секреты и настройки, управлять оплатой |
| Google Auth Platform | Управлять OAuth-клиентом, адресом возврата и публикацией приложения |
| Закрытый репозиторий GitHub | Менять исходники; после изменений запускать Manual Deploy в Render |

Google подтверждает аккаунт, но не членство в Discord. Перед выдачей доступа проверь, что человек состоит в проекте; при уходе отзови допуск. Подробности: [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

## Если что-то не заработало

| Симптом | Проверить |
| --- | --- |
| Кнопка входа неактивна | Оба ключа Google сохранены, почта владельца задана, сервис перезапущен |
| `redirect_uri_mismatch` у Google | Полное совпадение HTTPS-адреса и `/auth/google/callback`; без лишнего завершающего слеша |
| Адрес возврата указывает на `127.0.0.1` | Удалить ошибочно заданный локальный `APP_URL` и перезапустить до первого подключения |
| Вход есть, панели владельца нет | Выбран именно `liryzliryz34@gmail.com` |
| Приложение Google недоступно | Проверить Audience, тестовых пользователей и требования Google в консоли |
| После изменения адреса сервер не запускается | База привязана к адресу, Client ID и владельцу; порядок переноса описан в `SECURE_SETUP.md` |

Путь диска и почту владельца после запуска не меняй без переноса базы. База содержит доступы и сессии; резервное копирование делай согласованным способом SQLite, описанным в [SECURE_SETUP.md](SECURE_SETUP.md). Обновление сервиса с диском может ненадолго прерывать его работу.

Текущую старую копию в Sites оставляй закрытой. Отдельная публикация папки `dist` без Node.js откроет материалы в обход авторизации. Разрешённый читатель всё равно может сохранить прочитанное или сделать снимок экрана.
